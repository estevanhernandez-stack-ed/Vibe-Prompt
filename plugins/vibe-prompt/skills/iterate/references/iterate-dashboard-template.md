## Rendering rules

- "Why these now" section: brief (2-4 sentences), grounded in audit findings where they exist.
  If no audit.json was present, say: "Domain detection found your app covers [summary]. Suggestions
  based on inventory coverage gaps (no audit data available — run /vibe-prompt:audit for finding-
  grounded suggestions)."
- Each suggestion block: name as heading, all fields rendered. `exampleOutputShape` in a code
  block.
- `handoffHint` field: render as a clickable reference where possible (e.g., `/vibe-cartographer:scope`
  formatted as code so the user can copy-paste it directly).
- Auditor note: always at bottom, always present. This is the "don't treat LLM output as ground
  truth" reminder.
